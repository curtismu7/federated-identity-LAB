# federated-identity-LAB

Demo-tier standalone app: Ping release claims for Federated Identity (deck slide 40) and Self-Hosted Agents (slide 41), release 2026-11-02, plus the renaming on slide 35 (Federated Identity was Non-Human Identity; the console API object is still `NonHumanIdentity` at `/v1/nonhumanidentities`). Five in-process mock issuers each hold an RSA key and publish a JWKS; the lab's gateway does REAL RS256 verification (node:crypto) of the visitor's token step by step; a simulated Kubernetes sensor reports with its own token. **Every product claim is "Ping release claim, UNVERIFIED on our tenant"** (in the Mock or Real modal the page opens with, and on each claim's own tag; presenter mode too).

- Run: `./scripts/run.sh` (http://localhost:7400). Test: `npm test` (server is `node --test test/*.test.js`, a glob; web is vitest against the real Express app; scripts). Preflight `npm run doctor`. Reset `npm run reset`. Docker: `HOST_PORT=7400 docker compose up --build -d`. Node 26 only.
- Modes: **Mock** (default) = tables (`server/src/mockTable.json`, generated by `npm run mock-table` from 15 scripted scenarios run through the engine; a doctor check and a test fail on drift; read-only, every write is 409; no token or key is stored in it). **Live** = the real engine on the visitor's own actions. Both engines are loopback-only with zero outbound (netguard + a test); the one call that goes out is the Real-mode gateway check (below), only when run with `FID_GW_*` set. Mock never calls a gateway.
- Core: `engine.js` (one Engine per workspace and vertical: lab clock that only moves forward, five issuers, identities, keys, 15-step verification, mint, sensors, policy; no I/O; randomness injectable), `jwt.js` (base64url, parse, RS256 sign and verify, tamper), `keys.js` (lazy RSA pool, memory only), `catalog.js` (issuers, backends, seeds), `data.js` (claims, discrepancies, measured notes, presets), `scenarios.js` (+ Mock table builder), `actions.js` (the one dispatch), `clean.js` + `credentials.js` + `mask.js` (masking), `service.js`, `app.js`. Web: `useLab` hook, eight tabs; the Verify editor state lives in App.
- Rules that bite: the lab's claim names (node, pod, repository, environment, run_id...) are its own flat names; tag every claim per field ("deck claim", "console swagger name (schema only)", "lab reading", "lab-invented", "measured (our note)"); the deck says accepted across MCP and LLM gateways but our own 2026-10-21 MCP test did not prove it (say so); slide 57 still says Non-Human Identity (say it once); token-pass and the seven policy actions in the swagger are shown, not resolved; sidecar injection is in development: no behaviour claimed; the lab verifies RS256 only; everything the visitor types is masked in every answer, state, hop and log (`echo.test.js` types every shape everywhere); stored values (subject, audience, claims, namespaces) are strict forms and refused, never echoed, when credential-shaped; refusals keep honest HTTP status; writes are synchronous per engine; caps refuse the whole request (the audit log is a counted ring); a new workspace is refused at the cap, never by eviction; say "P1 Privilege Agent App", never the older word for it; ports 7400-7449; UI: shared `web/src/styles/standalone-ui.css` vendored byte-for-byte, app CSS tokens only (`bash ~/Development/AI-DEMO-Standalone/scripts/check-css.sh .`).
- Claims are signed EXACTLY as typed (no trim, decode or normalise; hidden characters shown as \\u{...}; credential-shaped or over-long claims refused); object keys are masked by `maskDeep` (every answer, values and keys); the parser is strict on both sides; the audit is three rings; unknown-kid refresh has a cooldown; Verify state is tagged with a (vertical, mode, generation) context.
- Browser check: `web/src/browserVerify.js` re-checks ONLY the signature with WebCrypto against `GET /api/issuers/:id/jwks` (public halves, Live only, same origin); never the full verdict; every failure is a result, never a throw; the Verify state lives in App; tabs sit in an ErrorBoundary keyed by vertical and mode and draw only when story, state, vertical and mode agree.
- Masking is the shared masker, version 1.4.0 (commit 9bc664a), copied UNCHANGED into `server/src/shared/` (`mask.js`, `hygiene.js`; one header line added). Never edit those two files: a masker fix goes to shared-masker (`~/review-air/shared-masker` on the Air), then copy again and name the version in the commit. `server/src/mask.js` creates the masker once (opaque names: `traceparent`, `traceId`, `mintedToken`, `n`, `e` plus three lab-written values by VALUE and the hop's shortened `Mcp-Session-Id` by PATH and VALUE (`trace.(listing|refusal).(request|response).headers`, at most 8 safe characters + `… (shortened)`; anywhere else the name stays masked); a second masker with `keyMode: 'none'` for lab-written prose: story, diagrams, Mock tables); `credentials.js` and `clean.js` are thin adapters that keep the old exports (`maskText`, `cleanFree`, `credentialShaped`, `tidy`, `reveal`, `maskedForm`). The lab's own policy on top: a claim or stored value with a run of 24+ letters and digits is refused (a SPIFFE ID has separators). Hidden characters in names and notes are written out (`\u{..}`) after masking, never deleted. Known masker gap, pinned in `corpus.test.js`: 34 of 3,416 probes are not masked after leading words (JSON blob, INI section, NUL blob, column list). Do not write a whole credential shape as a literal in a test (gitleaks 8.18.4 in CI): assemble it from parts at run time.
- HTTP edge (docs/EXPRESS-RECIPE.md of shared-masker): ONE route table in `app.js` (every route registered through `on()`) decides 405 with `Allow`; an unknown address is the fixed JSON 404 (no `Allow`); a charset other than utf-8 is a fixed 415 (value never read or logged); the catch-all error handler is last and never sends or logs `err.message`; the page shell answers `isPageAddress` paths only; `X-Workspace` is `default` or `w-<lab name>` accepted by `safeWorkspaceId`, a credential-shaped id is 400 `bad_workspace` BEFORE any slot exists and is never echoed; every JSON answer goes through `maskDeep` (values and keys) as a second layer behind the input cleaners. Tests: `hygiene.test.js`, `known-leaks.test.js`, `corpus.test.js`, `corpus-http.test.js`, `echo.test.js` (sweep in `sweep.js`).
- Crypto: RSA key generation only. Never generate EC keys (SIGABRT lesson).
- Settings: one shared file `~/Development/.env` (mode 600, `STANDALONE_ENV` overrides), parsed with `util.parseEnv` in `server/src/settings.js`; this lab takes only `FID_LAB_MODE` into its environment, never a bare MODE; the Real-mode gateway check separately reads `FID_GW_*` from the same file or the environment (the environment wins).
- Run check-drift, check-css and conformance by hand. SE k8s build deferred (owner, 2026-10-31); no k8s manifests. Catalog id D107 (assigned 2026-10-31, owner delegated the choice; not yet recorded in the standalone plan).
- "What Privilege did" (Rule 25): the Verify tab shows each gateway call through the shared `GatewayTrace` (`web/src/gateway-trace/*`, `server/src/gatewayTrace.js`, vendored byte-for-byte and pinned by `gateway-trace.sha256`; `scripts/gateway-trace.test.mjs` fails on a hand edit; never name a builder `trace.js`, that is the W3C helper). The lab's own builder is `server/src/verifyTrace.js`: the gateway here is the lab's simulation (`verifyCore`), so every trace is source `mock` and every decision `checked` (one per engine step, `skip` becomes `skipped`); the Verify panel carries a `basisNote` saying so. The one real gateway hop is the Real-mode gateway check (`POST /api/gateway-check`, `FID_GW_*` settings, shared `server/src/gatewayReal.js` with `capture: true`): its reply carries `trace.listing` and `trace.refusal`, each built by `traceFromDoor` (source `real`, decisions only `observed`/`inferred`, never `checked`), drawn by `web/src/components/GatewayCheckTrace.jsx`. Live puts `gatewayTrace` on the `/api/verify` reply (token text never in it, only its length); Mock adds it to each verify step in `/api/state` at request time (never into `mockTable.json`, whose drift test would fail). The stored-key call and the sensor report are not traced yet.
- Run observability (rule 27): the shared panel is vendored byte for byte (`web/src/run-observability/`, `server/src/runObservability.js` CORE ONLY, `scripts/run-observability-checkPin.mjs`, pin test `scripts/run-observability.pin.test.mjs`); never edit them, change the canonical in AI-DEMO-Standalone and re-vendor. This lab reads no logs, so there is no readers file and no `RUN_OBS_*` anywhere (a test pins it, the compose file mounts no Docker socket). The lab's half is `server/src/runObs.js`: `eventsOf` turns the answer of ONE engine operation (a table step in Mock, an action's outcome in Live) into events: agent = a mock issuer signing a token and the identity the gateway checked a token against (`info`), gateway = the lab's simulated gateway's verdict (allowed or refused at check N of 15), privilege = the lab's own Federated Identity model and sensor policy (a change is `info`; only an enforced sensor stop is `blocked`), person = the custodian of a stored key (`info`), Authorize and resource: never a row. Mock rows are built when the page asks, from the steps `mockTable.json` already holds (the table is never changed: its drift test would fail), at the lab clock, and each message starts with its step number. Live writes one stdout line per event (`runLog.live`; a request turned away before any decision is one `run=-` line) and builds no record: the wire value `real` is the lab's own local engine, so only the gateway check (`POST /api/gateway-check`, last 5 kept in `runLog.beginCheck`, the id returned as `runId`) is a Real record: `response` rows, never `logged`, at the time of the reply (call start plus the call's own `ms`, not after the helper's session close); a call with no reply is a line and no row, and the record is `partial`. `GET /api/run-observability` branches on exactly `real` and `mock` (any other mode answers a plain note). Never put a credential, a claim, a typed name, the agent key or the gateway address in an event; the stdout line avoids the words the shared matchers read (refused, denied, rejected, token, scope, served ...) and its actor is an id the lab wrote: `server/test/runObs.test.js` runs every line kind through the shared `classify()` for every product, with no field stripped. Recorder calls go through `safely()` so a throwing recorder never breaks a run or the audit, and tests use a silent run log. The one safety-test exemption: `server/test/entry.test.js` lets the vendored core, by the exact file name `runObservability.js`, skip the single assertion "no regular expression is built at run time" (its masking patterns come from constants and from escaped ids; the shared tests time them on 100 KB hostile lines); every other assertion there, and the netguard tests, apply to it unchanged.
- Real-or-mock modal: `web/src/mode-modal/` is vendored byte for byte from `AI-DEMO-Standalone/shared/mode-modal` (pin `mode-modal.sha256`, checked by `web/src/mode-modal.pin.test.js`); never edit it, change `shared/mode-modal/` first. It replaced the simulation banner; the lab's lines (Mock, Live = the modal's Real, and one for the moment before the mode is known) are `MODE_LINES` in `web/src/App.jsx` and carry the UNVERIFIED claim label. `/api/story` still sends its `banner` text (a server test pins it). Any Playwright or walk script must close the modal first (`mode-modal-ok`) or set sessionStorage `fid-mode-seen-mock` and `fid-mode-seen-real` to `"1"`.
