# Safety

- Loopback bind only (`FIDLAB_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1` only (a test pins it). The container runs as a non-root user, read-only, with every capability dropped.
- Host header must be a loopback name; writes must be same-origin.
- Netguard blocks every outbound connection (fetch, socket, DNS, UDP) with a self-test, and a test asserts zero attempts in the server process across the whole API in both modes. There is no worker thread and no child process. Every issuer is in-process and every address (`.example` names) is resolved by the lab itself: no JWKS is fetched from the network.
- **The lab holds no real credential.** All keys are RSA keys generated in memory by this process, shared by its workspaces, never written to disk and never shown (only the public half is published, and the state carries key ids, not key material). The credential a backend "receives" is a masked placeholder.
- **Credential-shaped values the visitor types are masked.** Names, descriptions and claims are cleaned on the way in (invisible characters deleted and the text NFKC-folded before matching, control and bidi characters removed, credential-shaped runs masked, and masking happens BEFORE any cut to length). Values the engine STORES and shows (an issuer, a subject, an audience, a pinned claim, a namespace) are validated against a strict form and refused, without being echoed, if they look credential-shaped. Every JSON answer is masked again by the specific detectors as defence in depth; the one exempt field is the lab-minted token the mint call returns, which can only contain already-cleaned claims. Error messages are fixed text and never include input; field names and ids in a path are never echoed. A test types every credential shape into every field, query, path, header and unknown key of every endpoint and searches every answer, the state afterwards and the process output for it. **Masking is a heuristic**: it can miss a secret, so do not type a real one.
- **What the token mechanics prove and do not prove.** The signature check is a real RSA verification, so an altered token fails it and a token signed by another key fails it. The lab accepts only RS256 (a lab limit). The lab cannot show that a real gateway behaves this way: the order of checks, the reason codes and the refresh rules are the lab's.
- **Honest status codes.** A refusal keeps its 400, 401, 403, 404, 409, 502 or 503; there is no flag that turns refusals into 200.
- Every value used as an object key or lookup (identity id, key id, issuer, vertical, scenario, claim name) is checked with a type test and `Object.hasOwn` or a list lookup; claim names that are `__proto__`, `constructor` or `prototype` are refused; decoded claims are copied with `Object.fromEntries`. A missing or wrong-typed argument is a violation.
- Writes are synchronous per engine, so a check and its change never interleave: parallel sensor enrolments, revocations and removals give exactly one winner each (tested over HTTP). A request that would break a cap is refused whole; nothing is dropped to make room. The audit log is a ring of 500 entries: the oldest is dropped and counted, and the page says so.
- Input is bounded: bodies 32 KB, a token 4096 characters, 12 extra claims, 5 audience values, 12 identities, 20 keys, 5 sensors, 200 findings (10 per report), 50 reports, 500 audit entries, 20 refresh-log entries per identity, 40 hops per answer; the lab clock moves at most 180 minutes per move and 10080 in total; an issuer rotates at most 5 times. Workspaces are capped in count (500, refused when full) and age (1 hour idle).
- The server writes no file (a test greps for write calls). The one home-directory touch is reading the optional shared settings file (`~/Development/.env`, or `STANDALONE_ENV`) with `util.parseEnv`, taking only `FID_LAB_MODE`. A bare `MODE` in it is ignored.
- Only `.example` and `.invalid` hosts appear in any shipped text (a doctor check scans the filled story in every vertical). The people, repositories, namespaces and nodes are synthetic.
- Every product claim is labelled "Ping release claim, UNVERIFIED on our tenant" in the banner of every tab, in presenter mode too. Field names from the console swagger of 2026-10-31 are schema only; the lab says so wherever they appear, and tags each field as a deck claim, a swagger name, a lab reading, lab-invented or measured (our note).
